# ES-0.2 — Inventario de flujo, proveedores y retención

**Actualizado:** 2026-10-13 · **Código revisado:** `5edfbd36dfcc6b1d083a57de77739de07f85e3c9` · **Estado:** implementación ES-0.2; QA de adjunto bloqueada por HTTP 400 de Blob en runtime local.

## Decisiones firmes de Toni

| Tema | Decisión | Consecuencia de análisis |
|---|---|---|
| Finalidad | Única: generar la valoración del usuario | OCR, visión y derivados solo se justifican si contribuyen a esa valoración. |
| Retención | 30 días desde `Assessment.createdAt`, con borrado manual anterior | Binarios Blob, metadatos y todos los derivados heredan el vencimiento del assessment; no se añade esquema. |
| Proveedores | Solo software de código abierto o coste cero; proveedor externo nuevo requiere aprobación expresa y comparativa previa | Se mantienen Neon y Vercel Blob; OpenRouter solo con modelos `:free` allowlisted y `data_collection: deny`; no se agrega proveedor. |

El plazo y la finalidad son decisiones firmes: binario, OCR/texto, campos extraídos, análisis visual y demás derivados vencen junto con el assessment a los 30 días desde `createdAt`; el usuario puede borrar antes. pdf.js/Tesseract.js para lectura de PDF permanece como fase futura y no se implementa aquí.

## Flujo actual (rutas observadas en el código)

```text
AssessmentWizard
 ├─ adjuntos/fuentes PDF ── @vercel/blob/client → POST /api/blob/upload → Vercel Blob privado
 │                                      └────── JSON POST /api/assessment → filas Neon + path Blob
 ├─ fallback multipart ──────────────────────── POST /api/assessment → función Next.js → Blob + Neon
 ├─ PDF con capa de texto → pdfjs-dist → parser CEE/presupuesto → datos derivados/Neon
 ├─ PDF con capa de texto → pdfjs-dist → parser → derivados/Neon
 ├─ imagen → Tesseract.js + Sharp (ENABLE_OCR) → OCR JSON/Neon
 ├─ visión de adjuntos → /api/assessment/[id]/vision/analyze → OpenRouter (condicional) → AttachmentAnalysis/Neon
 └─ análisis inmediato de foto → /api/ingestion/image/analyze → fallback local por defecto; Anthropic solo con `ENABLE_ANTHROPIC_IMAGE_ANALYSIS=true` y clave
```

### Logs y almacenamiento de derivados

No se consultaron logs live de Vercel; Runtime Logs puede mostrar salida `console.*` y metadatos de solicitudes según cuenta ([documentación](https://vercel.com/docs/logs/runtime)). Los errores de aplicación migraron a `src/lib/safe-logger.ts`, que escribe solo códigos de evento fijos; las rutas de upload/assessment/ingesta no serializan objetos Error, payloads, nombres, texto extraído, rutas ni cadenas de conexión. Los avisos OpenRouter y Catastro son constantes sin contenido de error. Los clientes emiten mensajes constantes. `src/app/api/leads/route.ts` conserva solo tipo de evento fijo y timestamp. Se añadieron pruebas sintéticas de centinelas para el logger. La inspección es del código y tests; no acredita la configuración de logging de plataforma ni una consulta live a Vercel.

`AssessmentAttachment` y las tablas derivadas pueden contener nombre, ruta y OCR/CEE/presupuesto/análisis. La decisión de borrado elimina estos registros junto al assessment y retira objetos Blob separadamente. No se añadió campo de vencimiento: servicios consultan con corte desde `Assessment.createdAt`; purga elimina filas con `createdAt <= now - 30 días`.

## Alternativas comparadas

Neon y Vercel Blob se mantienen por decisión firme de Toni; las alternativas de almacenamiento siguen sin selección ni autorización. Regla de coste se refiere a licencias/servicios del proveedor. Equipo, hosting, transferencia, operaciones y mantenimiento pueden costar aunque el software sea gratuito. No se habilita proveedor nuevo sin aprobación expresa de Toni y evaluación previa.

### Lectura PDF con capa de texto y OCR escaneado

| Opción | Licencia / coste software | Español y precisión esperada | Ejecución y ubicación del documento | Límites Vercel / esfuerzo / riesgo |
|---|---|---|---|---|
| **pdf.js** (existente, `pdfjs-dist`) | Apache-2.0; gratis | Español nativo en capa de texto; alta fidelidad al texto codificado, sin OCR ni corrección semántica | Puede correr en navegador o Node; hoy extracción observada en función Node. En navegador, bytes y texto permanecen en dispositivo hasta un envío explícito | Browser evita Function CPU/memoria, pero PDFs hostiles necesitan límites de páginas/tamaño y sandbox; esfuerzo bajo reutilizando parser; riesgo de PDF malformado/texto engañoso y grandes buffers. La evaluación de precisión para cualquiera de las herramientas requiere corpus sintético controlado (y luego corpus autorizado, si Toni lo aprueba) con verdad de referencia; no se atribuye un porcentaje de precisión sin medir. Las duraciones/memoria/tamaño exactos dependen del plan/región runtime, archivo y modelo; los límites de Vercel deben verificarse en el plan actual antes de diseñar trabajo síncrono.

Vercel documenta para functions Node.js límite de payload request/response de 4.5 MB y bundle máximo 250 MB; memoria habitual 2 GB (hasta 4 GB Pro/Enterprise) y duración máxima que depende de plan y Fluid Compute. Un PDF >4.5 MB no se puede enviar a API Function como multipart normal; el actual upload directo a Blob evita ese cuerpo, pero no la carga de procesamiento en la función que lee el Blob. Las cifras exactas deben comprobarse contra la cuenta/deployment antes de implementar ([límites oficiales](https://vercel.com/docs/functions/limitations)).

### Arquitectura candidata: “texto primero, OCR como alternativa” en navegador

1. El navegador lee PDF con pdf.js; si hay capa de texto útil, extrae texto localmente. Si no hay texto, ofrece o ejecuta OCR local Tesseract.js/WASM sobre páginas renderizadas, bajo límites explícitos de páginas/tamaño/tiempo.
2. Para PDF escaneado, el navegador renderiza páginas de forma acotada y usa OCR local; hoy no existe esta ruta para PDF, es propuesta.
3. El navegador muestra una vista previa para que el usuario corrija/acepte campos; la valoración usa los campos mínimos revisados, no trata texto automático como verdad.
4. Subida de binario solo si el usuario decide adjuntar/conservar evidencia para generar valoración; hoy el contrato de UX admite adjuntos. Si la función futura solo necesita campos, el servidor recibiría campos estructurados aprobados y fuente/estado/confianza/páginas, no PDF/imagen ni texto completo. No guardar ni transmitir texto completo por defecto.
5. Si Toni decide mantener el archivo adjunto, el binario sigue llegando a Blob (30 días confirmados). Solo los campos necesarios llegan a `/api/assessment`/Neon. Fallback multipart actual transmite el archivo al servidor y debe estar desactivado o rediseñado para una modalidad estrictamente local.

Esto reduce transmisión de contenido a OCR/IA externo y tiempo de CPU servidor; no elimina riesgo del navegador, memoria local, telemetría/errores del cliente ni el upload del adjunto que el usuario elija conservar. No se implementa ni se elige aquí.

### Incumplimientos confirmados frente a brechas por verificar

- **Incumplimientos de coste cuando se usan:** Anthropic Messages API cobra uso; Stripe aplica comisión a transacciones. Anthropic queda apagado por defecto y sin clave Production según Toni. Stripe ya existe fuera del flujo de documentos; queda como brecha del producto frente a regla estricta de coste cero.
- OpenRouter queda restringido por el código a `google/gemma-4-26b-a4b-it:free` y `qwen/qwen3.8-27b:free`; cada petición exige `provider.data_collection = deny`. Modelos de entorno fuera de allowlist se ignoran y, si no queda endpoint permitido, la función degrada localmente. El proveedor es software cerrado, pero el uso cumple el criterio alternativo de coste cero mientras solo se usen esos endpoints gratuitos.
- **No se afirma incumplimiento confirmado solo por licencia cerrada** para Vercel, Neon, PostHog, Resend ni OAuth, pues Toni acepta coste cero como alternativa a software abierto. Deben confirmarse plan, uso, límites, condiciones y región; mientras no, su cumplimiento queda **no verificado**.
- Tesseract.js/pdf.js/Sharp cumplen por licencia abierta; los recursos CDN de Tesseract no transportan el documento pero sí incorporan tercero externo y deben empaquetarse localmente o evaluarse/aprobarse si se elige esa modalidad.
- Catastro/Nominatim aparentan coste cero por endpoint público, pero faltan revisión de términos, retención y carga de dirección; no se atribuye cumplimiento final sin verificar.

## Retención y purga implementadas

- El vencimiento se ancla a `Assessment.createdAt`; `src/lib/assessment-retention.ts` calcula la fecha y considera vencida la valoración a partir del instante exacto `createdAt + 30 días`. Adjunto, OCR, extracción CEE/presupuesto y análisis heredan el mismo vencimiento.
- No se requiere migración: el schema ya contiene `Assessment.createdAt`; el cálculo deriva el cutoff y no añade columnas/tablas.
- `getOwnedAssessment` y la página de resultados excluyen registros vencidos. Las rutas de attachment, OCR, importación, visión y PDF que usan esta autorización dejan de servirlos. Checkout y estado de pago también filtran por el cutoff.
- `deleteAssessmentData` borra Blob y, dentro de transacción Neon, assessment, adjuntos y relacionados. `purgeExpiredAssessmentData` recorre assessments vencidos y continúa ante fallos por assessment, devolviendo contadores sin exponer identificadores. El endpoint `POST /api/cron/purge-expired-assessments` exige `Authorization: Bearer <CRON_SECRET>`. No se programa cron; la programación queda a decisión de Toni.
- Los objetos de draft abandonados antes de crear `Assessment` no tienen padre/`createdAt` y quedan fuera de este contrato de vencimiento. Requieren un diseño separado antes de prometer su purga automática.
- Riesgos: fallo Blob puede dejar filas para reintento; el endpoint informa fallos por cuenta, sin paths ni nombres. El tamaño de lote/timeout deberá revisarse si el volumen crece.

## Propuesta documental para función posterior de lectura

La función de lectura de presupuestos/PDF es alcance candidato para ES-0.3 o el lote que la matriz F0 asigne al tratar evidencia, CEE y presupuesto. No cambia los criterios existentes de ES-0.3 ni constituye fase aprobada. El almacenamiento ya está decidido (Neon + Vercel Blob); Toni aún debe elegir la herramienta de lectura/OCR después de esta comparativa y aprobar el alcance de una fase posterior, con spec separada antes de implementación.

Alcance a valorar: texto primero/OCR alternativo local; extracción solo de campos útiles para valoración de presupuesto/CEE; mostrar fuente, página, confianza, vacío y corrección por usuario; texto completo efímero en memoria; no enviarlo a logs, analítica, proveedor externo o Neon por defecto; el binario que el usuario conserve vence a 30 días y puede borrarse manualmente antes. Su QA sintético requeriría PDFs sintéticos con capa de texto, PDFs escaneados, páginas en blanco/giradas, baja resolución, tablas y caracteres españoles/acentos; resultados de referencia con valores conocidos; documento corrupto/grande, timeout, cero texto, OCR fail, cancelación y borrado; asegurar redacción de centinelas en errores y logs, y confirmación de expiración/derivados. No usar documentos reales ni SaaS externo en pruebas.
