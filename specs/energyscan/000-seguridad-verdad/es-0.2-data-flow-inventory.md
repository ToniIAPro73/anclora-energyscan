| Tema | Decisión | Consecuencia de análisis |

Se registra como semántica a confirmar antes de implementar la purga, sin reabrir las decisiones firmes de finalidad y plazo.

## Flujo actual (rutas observadas en el código)

```text
AssessmentWizard
 ├─ adjuntos/fuentes PDF ── @vercel/blob/client → POST /api/blob/upload → Vercel Blob privado
 │                                      └────── JSON POST /api/assessment → filas Neon + path Blob
 ├─ fallback multipart ──────────────────────── POST /api/assessment → función Next.js → Blob + Neon
 ├─ PDF con capa de texto → pdfjs-dist → parser CEE/presupuesto → datos derivados/Neon
 ├─ PDF con capa de texto → pdfjs-dist → parser → derivados/Neon
 ├─ imagen → Tesseract.js + Sharp (ENABLE_OCR) → OCR JSON/Neon
 ├─ visión de adjuntos → /api/assessment/[id]/vision/analyze → OpenRouter (condicional) → AttachmentAnalysis/Neon
 └─ análisis inmediato de foto → /api/ingestion/image/analyze → Anthropic (si hay clave) → respuesta al navegador
```

### Logs y almacenamiento de derivados

No se consultaron logs live de Vercel; esto es inventario estático del código. Vercel Runtime Logs muestran la salida `console.*` de funciones y su ventana depende de plan; el plan efectivo no se verificó ([documentación](https://vercel.com/docs/logs/runtime)). En el código aparecen errores de parseo multipart, errores Prisma/assessment y rollback, error genérico de imagen, errores OCR que incluyen nombre original del adjunto (`src/lib/ocr/index.ts`), error de visión con ID del adjunto y mensaje del proveedor (`.../vision/analyze/route.ts`, OpenRouter imprime modelo y mensaje de error, truncando cuerpo a 200 caracteres), y errores de Catastro/geocodificación. No se observó logging intencional de bytes/base64; los objetos Error de librería/DB podrían incluir detalles de entrada y requieren prueba de centinelas prevista en 0.2.c.

`AssessmentAttachment` mantiene nombre, ruta, fecha, OCR JSON/error/fecha, y `AttachmentAnalysis` contiene JSON detectado, resumen, confianza, avisos/error/modelo. CEE, presupuesto y filas derivadas también pueden contener contenido extraído. Las tablas tienen `createdAt`, pero no vencimiento. Borrar la fila principal elimina derivados relacionados por cascada; el objeto Blob requiere borrado separado y las valoraciones no tienen borrado de usuario identificado en este recorrido.

La evaluación de precisión para cualquiera de las herramientas requiere corpus sintético controlado (y luego corpus autorizado, si Toni lo aprueba) con verdad de referencia; no se atribuye un porcentaje de precisión sin medir. Las duraciones/memoria/tamaño exactos dependen del plan/región runtime, archivo y modelo; los límites de Vercel deben verificarse en el plan actual antes de diseñar trabajo síncrono.

Vercel documenta para functions Node.js límite de payload request/response de 4.5 MB y bundle máximo 250 MB; memoria habitual 2 GB (hasta 4 GB Pro/Enterprise) y duración máxima que depende de plan y Fluid Compute. Un PDF >4.5 MB no se puede enviar a API Function como multipart normal; el actual upload directo a Blob evita ese cuerpo, pero no la carga de procesamiento en la función que lee el Blob. Las cifras exactas deben comprobarse contra la cuenta/deployment antes de implementar ([límites oficiales](https://vercel.com/docs/functions/limitations)).

### Arquitectura candidata: “texto primero, OCR como alternativa” en navegador

1. El navegador lee PDF con pdf.js; si hay capa de texto útil, extrae texto localmente. Si no hay texto, ofrece o ejecuta OCR local Tesseract.js/WASM sobre páginas renderizadas, bajo límites explícitos de páginas/tamaño/tiempo.
2. Para PDF escaneado, el navegador renderiza páginas de forma acotada y usa OCR local; hoy no existe esta ruta para PDF, es propuesta.
3. El navegador muestra una vista previa para que el usuario corrija/acepte campos; la valoración usa los campos mínimos revisados, no trata texto automático como verdad.
4. Subida de binario solo si el usuario decide adjuntar/conservar evidencia para generar valoración; hoy el contrato de UX admite adjuntos. Si la función futura solo necesita campos, el servidor recibiría campos estructurados aprobados y fuente/estado/confianza/páginas, no PDF/imagen ni texto completo. No guardar ni transmitir texto completo por defecto.
5. Si Toni decide mantener el archivo adjunto, el binario sigue llegando a Blob (30 días confirmados). Solo los campos necesarios llegan a `/api/assessment`/Neon. Fallback multipart actual transmite el archivo al servidor y debe estar desactivado o rediseñado para una modalidad estrictamente local.

Esto reduce transmisión de contenido a OCR/IA externo y tiempo de CPU servidor; no elimina riesgo del navegador, memoria local, telemetría/errores del cliente ni el upload del adjunto que el usuario elija conservar. No se implementa ni se elige aquí.

### Incumplimientos confirmados frente a brechas por verificar

- **Incumplimientos de coste cuando se usan:** Anthropic Messages API cobra uso; OpenRouter enruta a inferencia que puede tener precio; Stripe aplica comisión a transacciones. Son llamadas/capacidades condicionales; su uso efectivo en Preview/Production no se verificó en configuración. En cuanto al coste, no se ajustan si se usan bajo facturación estándar.
- **No se afirma incumplimiento confirmado solo por licencia cerrada** para Vercel, Neon, PostHog, Resend ni OAuth, pues Toni acepta coste cero como alternativa a software abierto. Deben confirmarse plan, uso, límites, condiciones y región; mientras no, su cumplimiento queda **no verificado**.
- Tesseract.js/pdf.js/Sharp cumplen por licencia abierta; los recursos CDN de Tesseract no transportan el documento pero sí incorporan tercero externo y deben empaquetarse localmente o evaluarse/aprobarse si se elige esa modalidad.
- Catastro/Nominatim aparentan coste cero por endpoint público, pero faltan revisión de términos, retención y carga de dirección; no se atribuye cumplimiento final sin verificar.

## Brecha de retención de 30 días

- No se encontró expiración automática ni tarea de borrado en Blob; el borrado manual por attachment existe. Los objetos draft cargados antes de crear la valoración pueden quedar huérfanos si se abandona el submit.
- `AssessmentAttachment.createdAt` da una fecha de registro y el Blob puede exponer fecha `uploadedAt` vía API, pero el código actual no usa inventario/fecha de objeto para un barrido. El momento de subida debe ser el origen del plazo, incluso si creación de DB ocurre después.
- No hay `expiresAt` en `AssessmentAttachment`, `AttachmentAnalysis`, valoración ni resultados OCR. La fecha `createdAt` sola no representa necesariamente inicio de plazo de Blob.
- Para implementar: job recurrente/cola que detecte vencidos, borre primero objetos Blob y después filas/derivados de Neon de forma idempotente; proceso de huérfanos draft por timestamp Blob; borrado manual antes de vencimiento debe retirar derivados también; métricas/log categórico sin nombre, contenido o ruta sensible; proteger fallos y reintentos.
- Sin migración: posible barrido con `createdAt` para filas existentes y `uploadedAt` del proveedor para objetos draft si API/plan y completitud se confirman. Riesgo de carreras, timestamps ausentes y difícil auditoría. Con migración: `uploadedAt`/`expiresAt` y/o tabla de objetos draft, índices/estado de borrado; una columna y/o ledger permitiría trazabilidad fiable y reconciliación. No se recomienda decidir por etapa documental; cualquier migración requiere `QA_MINIMUM_FOR_DATABASE_MIGRATION=FULL` por contrato. La ruta del contrato está en `.anclora/PRODUCTION_RUNTIME.md` y no se modifica aquí.
- Definir antes de código si los derivados documentales y texto extraído se borran a los mismos 30 días. Recomendación de privacidad en este documento: sí; al borrar fuente, retirar OCR, análisis de imagen, extracción CEE/presupuesto y vínculos que reproduzcan contenido. Metadatos mínimos de auditoría podrían retenerse solo tras decisión explícita sobre alcance.

## Propuesta documental para función posterior de lectura

La función de lectura de presupuestos/PDF es alcance candidato para ES-0.3 o el lote que la matriz F0 asigne al tratar evidencia, CEE y presupuesto. No cambia los criterios existentes de ES-0.3 ni constituye fase aprobada. Antes de implementarla, Toni decidirá herramienta OCR y almacenamiento, y revisará si la lectura pertenece al alcance ES-0.3; luego actualizar la spec mediante cambio separado, sin anticipar criterios.

Alcance a valorar: texto primero/OCR alternativo local; extracción solo de campos útiles para valoración de presupuesto/CEE; mostrar fuente, página, confianza, vacío y corrección por usuario; texto completo efímero en memoria; no enviarlo a logs, analítica, proveedor externo o Neon por defecto; el binario que el usuario conserve vence a 30 días y puede borrarse manualmente antes. Su QA sintético requeriría PDFs sintéticos con capa de texto, PDFs escaneados, páginas en blanco/giradas, baja resolución, tablas y caracteres españoles/acentos; resultados de referencia con valores conocidos; documento corrupto/grande, timeout, cero texto, OCR fail, cancelación y borrado; asegurar redacción de centinelas en errores y logs, y confirmación de expiración/derivados. No usar documentos reales ni SaaS externo en pruebas.
